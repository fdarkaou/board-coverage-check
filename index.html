Board coverage check

An app is tracked only while it sits on one of your boards. Paste the list of competitor apps you care about and the board memberships read for them, and this page shows which apps are on no board (so nothing is being collected for them), which are on one board only (one cleanup away from dropping out), and which boards hold the rest, with item ids and notes. Paste an earlier report too and it lists what changed. Nothing leaves your browser; this page never calls the API.

Where to get the JSON

The input comes from PeekPanda, an iOS competitor catalogue where every app has a case file of dated, stored evidence. One memberships read answers for up to 100 apps; it is one call from your plan's daily API and MCP allowance, and so is the board list:

curl --get 'https://api.peekpanda.com/v1/boards/memberships' \
  --data-urlencode 'storeIds=493145008,570060128' \
  --header "Authorization: Bearer $PEEKPANDA_TOKEN" \
  --header 'x-genviral-tenancy: <selector from /v1/workspaces>'
curl --get 'https://api.peekpanda.com/v1/boards' \
  --header "Authorization: Bearer $PEEKPANDA_TOKEN" \
  --header 'x-genviral-tenancy: <selector from /v1/workspaces>'

Over MCP the same reads are boards with actions memberships and list. The board memberships reference lists every field. The command-line version on GitHub splits long lists into batches of 100, reads your ASO apps too, keeps a weekly diff, fails a CI job when an app is on no board and posts to Slack or Discord.

The read covers one tenancy (your personal space or one workspace). An app on no board here may still be tracked in another space you own. Free slots are the plan holder's allowance across every space they pay for.

Open source (MIT): github.com/fdarkaou/board-coverage-check. Example data is made up.
